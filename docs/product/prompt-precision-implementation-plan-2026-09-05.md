## 目标、边界与基线

修复 9 条原始 Prompt 重放暴露的需求解释、身份细化、推荐门槛和重复澄清问题。实现最小确定性规则，不重写 Backend、不建立本地商品目录、不引入新的模型或商业数据源。

基线为当前 0.17.20 工作树（包含上一轮未提交改动），本轮前 bundle SHA256 为 `371193aef375a0456244e83e61892e20003826b3fb8f76bf6198a7cecb3b045e`。原始本地证据在 `artifacts/prompt-replay-20260905/`。基线离线 14 项通过，但原始 Prompt 的三组最终购买推荐未完成。

输入为当前用户的公开购物需求及来源商品资料；输出为来源可核实的商品、需求证据、未核实项和明确终止原因。商品宣称不等于独立功效验证，商家已验证不等于品牌授权。

本轮只授权本地代码、测试与有界只读检索。不得提交、推送、部署、发布、升级版本或替换 Codex 缓存。不得模拟授权、扩大任意网络目的地、创建 Watch、支付或结账。不上调商品源/图片/补搜预算。既有未提交改动全部保留。

## 架构选择

沿用单一购物 Agent、类型化工具、服务器快照、共享执行层与既有来源适配器。只增加有限的需求归一化和安全身份细化；不增加生产多 Agent 流程。实现工作可并行，规则入口及最终验收由主实施者整合。

原意与解释分开：原始需求字符串/账本保留；规则只识别受控同义表达，不使用任意子串匹配。检索词负责召回，身份、用途、变体、商家信任共同决定能否推荐。不得通过降级用户要求来制造成功。

## 实施里程碑

### M1. 需求解释及商品宣称

- 将改善干燥、保湿、补水归入功效维度；将适合干性发质归入独立适用人群维度，二者不互相证明。
- 中文“改善干燥毛躁”等有限复合表达拆为可核验的功效，不要求 Agent 猜中唯一英文关键词。
- 相同明确功效出现在 requiredFeatures 或 primaryUse 时均进入必要条件；未知自由文本用途不自动硬化。
- 补充明确的商品级 dryness/moisture 宣称；保留原字段、引用位置、否定和范围。
- 成分、搭配条件、另一个商品、未经证实的疗效均不得转移给当前商品。
- 工具说明和 Skill 明确症状改善与发质分类的区别；继续保留自由文本兼容性，不增加多次工具往返。

### M2. 同目标内单调身份细化

- 允许同类 generic 查询细化到明确品牌/型号/角色，再细化到指定造型；沿用同一 goal、父快照和预算。
- 细化后输入简写类目不得清空已确认身份；跨类目、换角色、换型号须显式 CORRECT 或 NEW。
- 受控造型或颜色只写在完整 query 中也应有效，不强制模型重复提交 requiredFeatures；查询入口执行相同身份和造型证据检查。
- 审核过的中英文别名可以互认；未知翻译和任意附加词不视为身份等价。
- 接受合理的角色结构词 character/角色；作品与角色必须在同一商品证据内成立。默认造型必须绑定当前角色，不能借用别款的默认造型文字。
- 来源查询保留已确认身份，保持原有 Awin 校验及两轮检索边界。

### M3. 用途与显示门槛

- 将明确的 cosplay/角色扮演识别为必要用途；未知自由文本用途不一律变成硬要求。
- 只有商品级 cosplay 声明或完整的已识别作品、角色、假发身份才可支持该用途；颜色、材质、普通造型能力不足。
- 无完整目标身份依据的普通商品不得充当具体角色商品的研究卡补位。允许 0 条结果，不伪造同款或 alternatives。
- 可信、预算内、优惠多均不能覆盖用途或身份不足；所有重算路径保持相同必要条件。
- 排除明确只代表询价费或押金的商品条目，不能把部分款当作完整商品价格满足预算；普通定制商品或“无需押金”政策不因此被排除。

### M4. 有界澄清与未决兼容性

- 充电桩的前置澄清由服务器快照记录，每个目标最多一次，不接受模型提交“已澄清”标记。
- 续问仍缺国家/接口/整机信息时，允许有界商品发现，不循环返回相同前置问题。
- 缺失兼容性作为服务器拥有的未决条件进入商品评估，阻止购买首选、比较首选及变体重算绕过。
- 仅列出仍缺信息；地区或车型不得由 Tesla 品牌、语言、ZIP 或价格推断。
- 暂不改变其他类目的业务策略或放宽安装建议。

### M5. 全链路一致性

- 检查搜索候选、补搜候选、选中商品、变体和比较重算的约束传播。
- 继续使用不可变 selectionId/renderId、TTL、同会话校验、外部数据隔离和来源网络策略。
- 授权不可用/拒绝时停止浏览器路径；本轮不修改宿主权限或伪造弹窗。
- 商家验证缺口照实保留，不凭名称/评分自动升级信任。注册表扩充不在本轮范围。

### M6. 验收与记录

先补基线真实参数的失败测试，再做实现；组件测试和 MCP 工作流测试必须覆盖正例、否定、身份冲突、预算保留及缺少证据的负例。

完整检查：typecheck、lint、MCP build、全量测试、stdio smoke、git diff --check。构建后重新以三个独立 Agent 顺序重放原始 9 条消息，不提供预期产品、修复规则或后续消息；使用新的本地日志目录，保留基线证据。

验收标准：

1. 需求及预算跨轮无静默丢失；身份不得被缩写查询降级，跨身份替换必须明确。
2. 受控功能正例可核验；适用人群、成分、条件与功效不混同，否定优先。
3. 普通假发不成为 cosplay 的无证据首选，也不填充李白同款研究结果。
4. 充电桩不重复前置澄清；未确认兼容性时没有购买首选，已确认后可恢复正常判断。
5. 零权限绕过、零跨快照引用、零虚构信任/优惠/质量保证，原有相关测试不退化。
6. 实时检索不保证外部世界存在符合商品；失败须分别注明语义、召回、证据、商家信任、源故障或授权限制。
