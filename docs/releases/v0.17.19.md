# FindCheap Agent v0.17.19

## Qualified-result recovery

- Complete two-pass text searches with no verified fit can request one bounded
  web-recovery session even when research-only cards exist. Source outages and
  exhausted budgets remain incomplete, not evidence that a product is absent.
- Normalize bounded oily-scalp / anti-dandruff expressions and negations. Use
  compact discovery queries while retaining every hard requirement for final
  verification. Ingredients alone do not establish efficacy.
- Fix an empty-array color-classification bug: non-color requirements such as
  anti-dandruff or long sleeves must not become color selectors.
- Add host-consented `begin_web_search` and URL-only `complete_web_search` behind
  the shared executor and optional Backend capability. The host obtains consent;
  a model-authored boolean cannot grant it. One admission, no automatic renewal,
  60 seconds after approval, at most five merchant pages and three native cards.
- Reuse bounded HTTPS fetching, page-owned Product JSON-LD, exact offer/variant
  binding, requirement checks, merchant trust, ranking and native comparisons.
  Reject redirects, private-network targets, oversized pages and ambiguous offers.
  Preserve old immutable snapshots; new cards receive new references. No local
  product directory, cart action, invented Coupon or merchant-trust upgrade.

## Verification and limitations

The versioned release gate passed 1,006 tests across 75 files, including 46 added
regression cases. Typecheck, lint, MCP and Awin builds, full tests including stdio
smoke, and whitespace validation pass. MCP bundle SHA-256:
`771814e57e6714df28b5e6b81695de9db3c0f08cc0ce1c5d0ab4a09823ca9dba`.

A live shampoo continuation now retrieves anti-dandruff research candidates and
requests recovery when oily-scalp suitability is still unverified. Old cards
remain referenceable. Three live merchant-page probes were safely rejected for
missing structured data, network/policy failure or inadmissible price/offer data;
these were not successful recoveries or evidence of product absence.

The adapter requires bounded Product JSON-LD and a uniquely bound USD offer; it
is not an unrestricted DOM scraper or crawler. Hosts without MCP form elicitation
return PERMISSION_UNAVAILABLE. Protocol tests exercise synthetic approval and
URL-to-card-to-comparison handoff; actual Codex Chrome discovery, consent UI and
return-to-card acceptance are not claimed. Browser navigation remains host-owned.
See [the implementation and verification record](../product/text-search-recovery.md).
