# FindCheap Agent v0.17.22

## Scope and decision

Chris authorized the reference-handoff repair, commit, push, deployment to the
existing Railway production service, and installed Codex cache replacement.
This release fixes text-only tool-result consumption. It does not claim broader
merchant coverage, full-web acceptance, or general shopping accuracy.

## Defect and repair

Conversation `01a07168-c6e4-7eb2-8d26-46f1e5a3b3a2` stopped after a MacBook Pro
clarification because the server returned the goal and snapshot references only
in `structuredContent`. The caller forwarded only `content`, so the next request
could not supply its required parent reference. The failure occurred before any
merchant query. This output-contract defect was already present in v0.17.17.

The shared executor now appends a compact `findcheapContext` JSON text receipt
only after successful output-schema validation. It projects allowlisted server
references, continuation/recovery state, ordered card identifiers and compact
product facts. The original structured output, UI metadata and image blocks remain
available and unchanged. The receipt is not a substitute for full product/deal
evidence and does not grant authorization.

Receipts cover text/visual search, visual finalization, authorized web recovery,
comparison and selected-product operations. Variant inspection retains the new
snapshot and verified variant dimensions. Only complete snapshot `products` get
card positions; comparison entries and variant subsets use their exact IDs.

Tool and plugin instructions consistently accept the original `renderId` as
`parentRenderId`, or the original `goalId` plus `goalRevision`, including after
clarification. A missing-reference error allows one correction from the existing
receipt, not a guessed latest snapshot or a `NEW_PRODUCT` budget reset.

## Safety boundaries

- References remain bound to the same live immutable server snapshot. Expired,
  foreign and cross-snapshot references still fail closed.
- Source text remains fenced data. Undeclared output fields and private metadata
  are not projected; receipts do not come from input arguments or page content.
- JSON is not truncated. The compact receipt has a 23,000-character bound, and
  the existing 512 KB total tool-output limit is checked after projection.
- Merchant trust, price/variant binding, ranking, source request budgets, consent,
  checkout and payment boundaries are unchanged. No source, local catalog,
  permission expansion or automatic purchase is introduced.
