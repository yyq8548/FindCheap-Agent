# FindCheap Agent v0.17.20

## Text recovery and requirement continuity

- Distinguish host consent refusal, cancellation, unsupported capability, timeout,
  and interface errors. Bind consent to the active tool request and cancellation.
  Only classified transient failures allow one further consent attempt on the
  same immutable snapshot; refusal, cancellation, expiry and used sessions stop.
- Record safe consent status, attempt, capability and duration, without raw host
  errors, credentials or session tokens. An interface failure is not evidence
  that the user refused permission or that no product exists.
- Use short discriminating category queries, including a bounded second web query,
  while retaining every hard requirement for final source-evidence validation.
  Exact-product and image workflows retain their existing safety boundaries.
- Allow explicit withdrawal of individual required features without clearing
  unrelated requirements, budget or size. Ambiguous shopping-use changes clarify
  before retrieval; symptoms and negative answers do not silently reset context.
- Fold research-only cards by default and expose missing evidence prominently.
  Existing cards, selection controls, immutable snapshots and comparisons remain.
- Qualified products with only unverified merchants may request one authorized,
  bounded web recovery. Remaining unknown merchants produce a report-only result,
  never an invented verification action or automatic trust promotion.

## Verification and known limitations

The versioned release passed 1,022 tests across 76 files, including network-forbidden
MCP dialogue replay and built stdio smoke. Typecheck, lint, MCP/Awin builds and
whitespace validation passed. MCP bundle SHA-256:
`59492d861d4196793b6e67b81bf8a71257c712b288d2df0b34167d2b7f84f6a0`.
Local synthetic
browser inspection verified initial folding, expansion and visible controls.

Actual Codex consent UI, Chrome discovery and the installed widget handoff remain
unverified. Synthetic protocol tests do not establish live-host acceptance, live
provider recall, language interpretation or visual accuracy. The original generic
NOT_AUTHORIZED response does not identify its underlying host failure.

Security remains fail closed: no browser recovery before host approval, no budget
renewal after admission, at most two discovery queries/five merchant pages/three
cards in 60 seconds after consent. Server-owned URL, offer, variant, requirement,
trust and snapshot checks remain. No local product catalog, checkout, purchase,
new merchant approvals or broader redirect permissions are introduced.
