# FindCheap Agent v0.17.29

Runtime `0.17.29`; package `0.17.29+codex.20260907153518`. This is a scoped reliability repair, not whole-design acceptance. [Research, alternatives, frozen repair plan and original-case evidence](../engineering/changes/2026-09-07-qa-network-recovery.md).

## Release decision and frozen sequence

Chris authorized committing, deployment and installed-cache update after reviewing the repair limitations. The subsequent discussion of shopping-record retention was a request to draft a decision question, not approval to change lifecycle rules. No memory, payment or Watch retention behavior changes in this release.

Research: GitHub `main`, Railway production and installed Codex were v0.17.28 at release start. Baseline commit: `7509cac5217790345a2852eb810c11520bb03cc4`; prior production deployment: `0a43170f-1f1d-4e87-bde2-aa3efbaf2ade`. Existing patch is the reviewed QA repair. Node 24, pnpm 10.34.5, existing MCP/Awin build paths and no dependency/schema migration are retained.

Options: (A) keep runtime 0.17.28 and change only the versioned package suffix, requiring hash-based distinction between two runtime-identical releases; (B) publish patch runtime 0.17.29 and a new cache directory, with explicit source/production/install identity. Choose B. Both avoid overwriting a locked running cache; B makes rollback and verification clearer at the cost of synchronized version metadata.

Frozen order: version metadata and release notes → MCP/Awin builds → typecheck/lint/full default tests/stdio/diff checks → commit and push → explicit existing Railway production service deployment → health/readiness/read-only source checks → marketplace upgrade/install → installed bundle hash and stdio verification. Inspect database-backed registry precedence before claiming the new official host is live. Do not create a new Railway service, alter provider credentials, delete user state or force an occupied cache.

Decision: LIMITED GO for verified repairs, contingent on the release gates below. Whole-design acceptance remains NO-GO. Rollback source is the previous v0.17.28 commit and retained versioned plugin; the replaced deployment may require redeploying that source rather than restarting a removed instance. No state migration is introduced. Identity/authorization failure, broken readiness or sustained source regression blocks rollout and requires rollback/containment. Ordinary transient source failure preserves last valid Feed snapshots.

## Changes and safety

- Classify sanitized DNS/request/body transport failures separately from policy and TLS rejection. Typed transient failures can retain existing host-authorized recovery eligibility; unknown and unsafe failures stay closed.
- Retry eligible interactive candidate-image transport failure at most once, in the execution layer's original request/time/cancellation budget. Retry is not added to Watch, quotes or Feed adapters. Safe code/phase/source-host diagnostics do not expose private URLs or error bodies.
- Repair Sony official search poisoning by unrelated observations and narrowly ignore incomplete, nonselected, hidden, unavailable same-model sibling metadata. Selected model/SKU/URL/color/price/stock checks remain mandatory.
- Add the reviewed exact medicube US official host to embedded/default registries. Current managed trust is authoritative: an embedded seed never bypasses a missing managed approval. This does not verify the original requested 155g package.
- Distinguish omitted prior references, unavailable process-local state and known expiry. Correct references are not retried endlessly when their state is gone. No cross-restart shopping memory is implemented.
- Add a read-only preflight and frozen original-case replay. Protocol presence and loaded candidate images are not native-host or image-accuracy acceptance.

Nine comparison rows, source-owned prices, exact identity, immutable selection IDs, trust/quality separation, one-use quote approval, no automatic purchase/payment and bounded URL/redirect validation remain unchanged.
