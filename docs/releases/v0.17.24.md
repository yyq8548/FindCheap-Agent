## Proposal and frozen release sequence

| Route | Benefit | Risk / cost |
| --- | --- | --- |
| New versioned package and explicitly targeted production deployment | Source, runtime and installed files can be independently verified; preserves the previous cache | Requires metadata updates, complete release gates and a Codex restart |
| Replace the existing same-version cache in place | Fewer metadata changes | Active processes can lock files; source provenance becomes ambiguous and mixed versions are possible |

Select the versioned route. Freeze the sequence: update only release metadata and exact version expectations; immediately rebuild MCP and Awin artifacts; run focused version checks, typecheck, lint, the full default suite, stdio smoke and diff checks; audit the payload; commit and push to `origin/main`; verify CI and remote SHA; explicitly deploy the existing production target; verify SUCCESS, health, readiness, bounded search and artifact hash; refresh only the FindCheap marketplace and install the new version; verify enabled state, distributed-file equality and installed stdio.

No new feature work, database migrations, source expansion, merchant approvals, real carts, real Watches or private image artifacts are authorized by this release sequence. Local tests, GitHub CI, deployment and installed-cache checks are separate gates; installation does not hot-reload an already running MCP.

## Changes

- Visual search retains unavailable same-item information and can recommend reviewed, purchasable similar items with explicit differences. Similarity never becomes exact identity. Hard requirements, trustworthy merchants, reliable stock and source-proven same-brand evidence for alternate colors remain enforced. Native and web-recovered results share these gates and terminal messages.
- Text and visual retrieval share 90/180-second monotonic service-observed flow deadlines, cancellation and late-result rejection across native continuation and authorized web recovery. Existing 30-second active-network, request and per-tool limits remain. Only actual authorization waiting pauses the flow clock; this is not a complete host-user-turn SLA.
- Explicit anonymous-cart quotes require a current accepted MCP form and a short-lived, single-use permit bound to the exact offer, variant and US ZIP. Fixed Shopify API, quantity and returned-identity checks reject forged, stale, copied, replayed or cancelled authorization. Search and Coupon research do not create carts. Delivered-total Watches cannot call Cart APIs.
- Watch storage uses revision checks, bounded exclusive locking and atomic replacement. Minimal deletion tombstones prevent resurrection and preserve pending stop identifiers. Reliable first restock transitions persist a stable completion event and local stop intent; late results cannot reactivate paused, completed or deleted rules. Local stop intent does not prove the host scheduler actually stopped.

## Rollback and containment

Retain the previous source/package and Railway deployment `efbece61-aa13-4a38-9f5a-3bfb153a8b37`, including the existing persistent Feed snapshot volume. The Feed persistence format is unchanged. If the upstream release is unhealthy, redeploy that verified service revision without deleting the volume.

Plugin downgrade is not automatically state-compatible: older Watch writers may reject new terminal fields or ignore the new locks and tombstones. Do not run old and new Watch writers concurrently, delete Watch data, strip tombstones or discard pending stop identifiers to force rollback. Stop affected MCP/Watch writes first, preserve state, and assess compatible migration or a forward fix before restarting an older writer. Keep the old cache intact when locked; install the separate new cache and restart Codex to load it.
