# FindCheap Agent v0.18.6

This release repairs problems found while testing product search, selected-product inspection and Windows upgrades. The final R4 package passes the complete default suite: 210 files, 4,116 assertions. Runtime commit `3228e22` is pushed, both CI workflows passed, and the exact distribution is installed and verified. Native Glossier search and variant inspection now pass; broader native and manual acceptance remain in progress. Earlier candidates and failures remain recorded separately below.

## Changes

- Treat a category request such as “Nespresso Original compatible coffee capsules” as category discovery. Compatibility wording stays in the requirements instead of becoming an exact product name. Budget, brand, model and selected-variant constraints remain enforced.
- Isolate every version of an Awin product key when its normalized records disagree across feeds. Fully identical records retain one copy; the service does not choose a conflicting price. Duplicate keys within one feed still fail validation. Health metadata separately records input, excluded and deduplicated rows.
- Preserve successfully validated Awin source-cache metadata when aggregate publication fails. Unchanged sources can be reused after retry or restart. Validation failures and the local request quota wait for the normal refresh cycle; temporary network failures retain bounded retries.
- Recover Shopify prices only from evidence bound to the selected product, variant, SKU, amount and currency. The inspector safely parses supported Web Pixels data without executing page scripts. Conflicting or ambiguous evidence remains unknown; parent prices and global currency labels cannot supply a variant price.
- Keep product-edition evidence attached to the current product. A medicube FAQ recommendation for a separate Mild product no longer makes the original SKU conflict with a “not Mild” requirement. Missing edition or net-weight evidence remains unknown.
- Compare same-product offers when one source repeats an already verified condition as a variant option. Unknown or conflicting conditions, different colors, packaging and identity conflicts still prevent comparison. Merchant trust is unchanged.
- Preserve the verified product and variant behind an exact Shopify URL through search, selection, inspection and persisted state. Different products and conflicting variants are excluded by default. Explicitly requested alternatives remain labeled as research alternatives through inspection, never confirmed copies. A globally confirmed retailer offer can change its own variant when the user requests the option and the provider verifies the same parent product. Contradictory Shopify variant IDs and URLs are rejected; affiliate and WooCommerce local IDs are not treated as Shopify IDs.
- Keep product anchors server-owned and reject public argument injection. Restore valid WooCommerce anchors with a strict private snapshot codec after recreating the service in the same trusted task; cross-task access remains rejected. This closes a newly reproduced recovery failure, without claiming native UI or desktop-restart acceptance.
- Accept recognized attribution parameters on selected Shopify links without changing product identity. Unknown or semantic query parameters, duplicate or conflicting variant IDs, wrong merchants and wrong parent products remain rejected. Local identity mismatches no longer masquerade as upstream schema errors; real provider errors retain their classification.
- State the existing visual-review argument limits in the tool and skill instructions: brief evidence of at most 160 characters, with each attribute appearing once per verdict. Validation remains strict. The original overlong/duplicate-attribute native failure and its successful single correction remain recorded.
- Protect the existing Windows plugin cache before invoking the Codex installer. Restore missing old files without overwriting concurrent changes, and verify installed/enabled state plus the exact distribution file set and hashes. Installation failures remain failures.
- Correct GR-Research headphone/brand routing and the existing Orleans Coffee canonical origin. Add Hidden Secrets Wigs as a search source with standard priced color variants, bringing the access table to 1,003 stores. An explicitly false optional SKU becomes missing rather than invalidating the whole response; other invalid SKU values and product/parent/variant checks remain enforced. Redirect restrictions and merchant-trust boundaries remain unchanged.
