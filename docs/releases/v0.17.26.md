## Changes and safety

- Preserve reviewed official product URLs and resolve identity from the existing source adapter. Explicit source-confirmed variant color and size survive subsequent comparison; a representative size is not promoted into a user requirement. Unknown hosts and unsafe selectors do not acquire trust.
- Add explicit `compareMerchants` intent. One qualified source can satisfy ordinary product search but not an explicit cross-merchant comparison. Authorized recovery retains and revalidates original candidates; newer observations supersede stale stock or prices.
- Preserve bounded source-owned product descriptions during requirement inspection without hiding negative evidence behind truncated text. Merchant trust and evidence requirements remain unchanged.
- Keep image corrections on the visual tool and the original search budget, with at most two review rounds. Ambiguous categories can be clarified before retrieval. Server-observed clarification waiting is reported separately, not represented as verified human waiting.
- Project visual outcomes, supported differences, recommendation scope and stock scope into model-visible receipts. Clear obsolete questions and distinguish bounded summary omissions from missing evidence. Second-pass queries retain an existing recognizable structural cue.
- Resolve a single quote from exactly one synchronized selection in the specified snapshot. Distinguish no selection, multiple selections, invalid references, unsupported quotes and temporary failures; preserve exact variant, ZIP and real host authorization requirements.

No new shopping tool, arbitrary network proxy, local product catalog, merchant approval, runtime dependency, Watch scheduler or persistence migration is introduced. Image similarity cannot establish exact identity. No authorization bypass, automated purchase, fabricated Coupon, or commission-based ranking is allowed.

## Release research, alternatives and frozen sequence

Baseline source is `3f4a058da023eb8ca52aa56798ed9fccab22a94b`; origin/main matched it before release. Existing scripts build the local shopping MCP and the separate Railway Awin source service. Shared runtime version feeds the plugin metadata, skill display and builds. GitHub CI independently checks reproducible bundles, lint, types, tests and Windows installation packaging.

| Approach | Benefit and risk | Cost and rollback |
| --- | --- | --- |
| New semantic/package version, then normal marketplace upgrade (selected) | Clear artifact provenance; existing processes still need restart | Metadata and rebuild only; preserve the previous cache and production deployment |
| Repackage under the current version and reinstall | No semantic bump, but ambiguous identity and possible active-cache locks | Less metadata work, weaker rollback identification; not selected |

Frozen sequence: (R1) update only release metadata and notes, build MCP/Awin and assert version consistency; (R2) run full default tests, typecheck, lint and diff validation on the release artifact; (R3) commit/push and check remote SHA/CI; (R4) deploy the existing explicit Railway production target and verify SUCCESS, health, readiness, bounded read-only search and artifact hash; (R5) upgrade only the FindCheap marketplace/package and verify enabled state, source/cache hashes and installed stdio. Failure holds the affected step; no force push or forced locked-cache replacement.

Restart Codex and open a new task to ensure the new MCP and skill load; updating cache does not hot-reload a running process.
