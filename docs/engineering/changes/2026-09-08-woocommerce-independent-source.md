## Implement

- P1–P6：共享 schema、五店独立访问表、固定路径安全读取、simple/variation 归一化、跨店聚合、覆盖／失败／预算计数、搜索缓存、熔断、取消及图片引用；服务默认关闭。
- P7–P8：`Backend.catalog.woocommerce` 与 `product.woocommerceProducts`，可选 HTTPS 客户端；首轮与既有来源并发，品类查询也参与，最多两轮；保留原始 Woo DTO 和来源状态。
- P9–P10：原快照复制保存来源对象，跨店数字 ID 不串商品；统一事实投影用于过滤、混合比较、去重和优惠。通用 inspector 加兼容名；先核验全部有限规格再截取三条，父快照不变。选中优惠先尝试刷新原 ID 的价格，缺映射不伪造适用性。
- P11：Woo 视觉来源／指纹／候选和安全代理图片接入已有复核；不上传用户原图给商家，换规格或图像证据失配撤销旧视觉资格。
- P12：Woo 独立 Watch 目标和文件后缀、共享锁／容量、观察器及回调分发。创建前刷新目标并原子保存库存基线；无效、跨商家、迟到、未知库存均不通知；只接受锁定规格的真实库存转变。未创建真实 Automation。
- P13：配置示例、插件环境变量、两个购物技能、v41 UI、总设计和[运行手册](../../product/woocommerce-source-setup.md)同步。

每个原子模块均完成对应局部构建后跑相关断言。源服务的 schema／安全读取／聚合／HTTP 模块由源构建验证，MCP 端口、候选、卡片、检查、Watch 及审查修复逐次执行 MCP 构建；两边产物独立，未并发覆盖同一 bundle。最终全量结果见下。

没有新增运行依赖、商家信任记录、联盟批准、购物车／支付路径或全量商品数据库。旧 Awin、Shopify 和 eBay 端口保留。

## 审查修复与计划差异

- 子变体属性覆盖父范围；父范围不能反过来覆盖选中颜色／尺码。保留指向所选规格的 URL。
- API 和图片重定向在第二个请求前拒绝；取消、字节／请求限制和真实计数保留。
- 跨店结果按店交错收集后再限制数量，防止首店占满；空注册表不报告完整覆盖。
- 快照对原始 DTO 做复制；检查规格先过滤再限三条；未知库存不成为 Watch 的缺货基线。
- Woo 视觉指纹绑定 merchant/product/parent/variation，检索、图片展示、复核和最终元数据统一；变体改变清除原相似标签与复核证据。
- 选中商品 lookup/inspect 不采用原计划 30 秒详情缓存：创建 Watch 与后续检查要求新观察。搜索仍使用 60 秒受限缓存。
- 首版采用代码硬预算而非新增可调预算环境变量，避免扩大配置面。测试文件按实际职责组织，覆盖目标沿用 P1–P13，不机械保留计划中的拟定文件名。
- 配置五家访问商家，候选分母仍是八家；未添加 Nalgene（预算不符）、Nutribullet（忽略搜索）或 Landyachtz（403）。访问通过不提升商家信任。

## P14 与独立验收边界

源码包可审查，来源默认关闭。发布顺序仍为：授权后先部署兼容来源服务 → 核验并开启小范围 → 分发新插件 → 核对安装启用状态、source/cache hash 和 stdio → 原生宿主验收。

真实 Codex 图片加载／卡片选择／混合比较与完整优惠轨迹尚未验收；真实 Watch 创建、调度、重启和停止需明确测试规则授权及宿主证据。SDK 内存传输只证明注册工具及本地状态行为，stdio 只证明进程协议。生产 SLO 和最终商家有效推荐覆盖也保持待验收。未通过这些门槛前不宣称“全链路上线”或整个 Agent 设计完成。
